For security testers

ByteForge is the storefront skin over DjangoGoat, an intentionally vulnerable Django app. Every category below is reachable through the normal storefront flow (search, order tracking, account settings, support tools) as well as directly by URL. Every vulnerable endpoint has a -safe counterpart for true-negative testing.

Reflected XSS

OWASP A03: Injection · via the nav search bar

Query param written into the page with autoescape off vs. Django's default template escaping.

/xss/?q= /search-safe/?q=

SQL injection

OWASP A03: Injection · via /track-order/

Raw f-string SQL vs. a parameterized ORM query.

/sqli/?id= /sqli-safe/?id= /track-order/?order_id=

OS command injection

OWASP A03: Injection · via /support/ diagnostics tool

Shell string built from unsanitized input (shell=True) vs. a validated hostname passed as an argument list.

/tools/ping/?host= /tools/ping-safe/?host=

Path traversal

OWASP A01: Broken Access Control · via product "Download Spec Sheet"

Unsanitized filename join vs. a resolved-path sandbox check.

/files/read/?name= /files/read-safe/?name=

Open redirect

OWASP A01: Broken Access Control · via /support/ partner deals link

Unvalidated next param vs. a fixed allowlist of local paths.

/go/?next= /go-safe/?next=

Server-side request forgery (SSRF)

OWASP A10: SSRF · via /support/ compatibility checker

Server fetches any attacker-supplied URL vs. an allowlisted internal destination only.

/fetch/?url= /fetch-safe/?url=

Mass assignment

OWASP A04: Insecure Design · via /account/settings/

A hidden role form field is applied with no whitelist — tamper with it and re-submit. JSON API equivalent: POST /profile/update/ with {"role": "admin"} vs. the whitelisted /profile/update-safe/.

POST /account/settings/ POST /profile/update/ POST /profile/update-safe/

CSRF

OWASP A01: Broken Access Control

@csrf_exempt state-changing POST vs. the default CsrfViewMiddleware protection.

/transfer/ /transfer-safe/

Broken access control / IDOR

OWASP A01: Broken Access Control · via /account/orders/

Order lookup with no ownership check vs. one scoped to request.user. Also: an "Employee Portal" reachable by any logged-in user.

/orders/<id>/ /orders/<id>/safe/ /admin-panel/

Django DEBUG exposure

OWASP A05: Security Misconfiguration · via footer "Report a Site Issue"

DEBUG=True renders a full traceback with settings and request metadata on any unhandled error.

/trigger-error/

Weak cookies

OWASP A05: Security Misconfiguration

Cookie with no Secure/HttpOnly/SameSite vs. one with all three set.

/set-cookie/ /set-cookie-safe/

CORS misconfiguration

OWASP A05: Security Misconfiguration · the "price check" partner API

Reflects any Origin with credentials allowed vs. no CORS headers at all.

/api/cors/ /api/cors-safe/

Information disclosure

OWASP A05: Security Misconfiguration · linked from /robots.txt

An accidentally web-accessible backup file shaped like a real config dump (all fake values).

/backup.sql.bak

Seeded accounts: alice / bob, password lab-password-123. Full endpoint reference and setup instructions are in the README.
